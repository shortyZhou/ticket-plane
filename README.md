# ticket-plane：四平台机票比价 Skill

本项目提供 [flight-price-search](skills/flight-price-search/SKILL.md) Skill，用于指导 Codex 按指定行程查询携程、飞猪、同程、去哪儿的单程机票和往返组合报价。它是一套查票与核验工作流，并不提供平台官方 API，也不会在后台自动抓取或订票。

## 能做什么

- 按出发地、目的地、可接受机场、日期和**起飞时段**筛选单程航班，比较四个平台当次页面显示的起价。
- 在各平台的往返搜索页逐个选择符合条件的去程，读取每个可访问返程对应的**往返组合报价**。
- 对齐航班号、实际承运航班、机场和时间，标注代码共享航班，避免把同一物理航班重复算作不同班次。
- 在对话中输出比价表；用户需要时，可整理为 Excel，并记录来源、查询时间、报价口径和未查得价格的原因。

Skill 不预设航线、日期、时段或乘客条件。每次查询都从当时可访问的页面重新读取，历史结果仅供参考。仓库中的 `上海_潮汕 机票比价.xlsx` 是一次历史查询的示例，不代表当前可购买价格。

## 安装与调用

本机已将 Skill 安装在 Codex 的 `~/.codex/skills/flight-price-search/`。在其他电脑使用时，把仓库的 `skills/flight-price-search` 文件夹复制到该目录；也可以在支持项目 Skill 发现的环境中按其要求配置。

在 Codex 中明确调用：

```text
使用 $flight-price-search 查询：
去程：<出发城市及可接受机场> → <目的地城市及可接受机场>，<日期>，起飞 <时间范围>；
返程：<日期>，起飞 <时间范围>；
<人数>位成人，<舱位>，<直飞或中转偏好>。
请比较携程、飞猪、同程、去哪儿的单程价格和实际往返组合价格，附查询时间与页面链接。
```

只查单程时省略返程条件。需要 Excel 时，补充文件保存位置与工作表要求；需要全部组合时，明确要求列出所有当次页面可访问的符合条件组合。

## 查询方法

### 单程

四个平台使用同一组旅客、舱位、日期和机场条件分别搜索。按起飞时间筛选后，记录航班号、出发与到达机场、起飞与到达时间、直飞或中转状态及页面起价。对代码共享航班核对实际承运航班；某平台没有展示的航班号，其价格留空。

携程在当前环境可选用已验证的 OpenCLI `ctrip flight` 命令读取单程列表，再核对页面信息。该命令的列表首个报价属于页面起价，不能推导往返价。飞猪、同程、去哪儿使用当次可访问的搜索页面；是否能读取结果取决于页面状态、登录和验证码等条件。

### 往返组合

必须在**同一平台的往返搜索页**选择去程，再读取该去程下每个符合条件的返程及其组合价。选择不同去程后，需要重新查看返程报价。两段单程价格之和、最低价日历数字都不能当作具体组合价。

| 平台 | 组合报价的读取方式 |
| --- | --- |
| 携程 | 选择去程后，读取返程列表中对应航班的“往返总价”。 |
| 飞猪 | 选择去程并进入返程或票档页面，看到具体组合总价后记录；若被登录或页面限制挡住，价格留空。 |
| 同程 | 选择去程后，读取返程列表对应组合的“起”价。 |
| 去哪儿 | 核对往返页的基础起价与所选返程“补”价，计算页面组合报价，并尽可能与底部总价核对。 |

页面布局及计价字段可能变化。实际操作以当次页面可核实的组合总价为准；无法确认时写清原因，不猜测价格，也不把连接失败说成无票。

## 结果与价格口径

单程表按航班和时间对齐四个平台；往返表按“去程航班 + 返程航班”对齐。每条报价应能追溯到平台、查询时间、搜索链接及页面标价口径。若导出 Excel，可分别使用“单程机票”和“往返组合”工作表，并在保存后核对组合数量和代表性价格。

搜索列表价通常是“起价”。除非在结算页核实，否则不称为含税最终支付价。行李额、退改规则、实际经济舱票档和税费未核实时写“未知”。平台要求登录、触发验证码、连接失败或超时时，保留空价并记录具体原因。
